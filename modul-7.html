Claude Code, Git ve Güvenli Proje Geliştirme

Programın "üretim" aşamasına giriyoruz. Bu modülde Claude Code ile gerçek kod yazacak, Git ile her değişikliği güvenle kaydedecek ve hatalı bir adımı saniyeler içinde geri alabilecek yetkinliği kazanacaksın.

⏱️ Tahmini süre: 90-120 dakika 🎯 Ön koşul: Modül 2, Modül 3 🧰 İhtiyacın olan: Kurulu Claude Code + Git

1Claude Code arayüzünün ve çalışma yöntemlerinin tanıtılması

Claude Code, terminalden çalışan bir kod geliştirme ajanıdır. Kullanıcıdan doğal dilde bir görev alır, ilgili dosyaları okur, değişiklik önerir ve — onayınla — bu değişiklikleri gerçek dosyalara uygular.

Terminal, Visual Studio Code ve masaüstü üzerinden kullanım

Modül 2'de kurduğun gibi, Claude Code'u üç ortamdan da çalıştırabilirsin: doğrudan terminalden (claude komutuyla), VS Code'un gömülü terminalinden veya (varsa) masaüstü uygulamasının entegre görünümünden. Bu modül boyunca terminal + VS Code kombinasyonu üzerinden ilerleyeceğiz.

2Mevcut bir kod projesini yapay zekâya tanıtma

Var olan bir projenin klasörüne girip claude komutunu çalıştırdığında, Claude Code önce proje yapısını tarayarak neyle çalıştığını (hangi dil, hangi dosyalar) kendiliğinden anlamaya çalışır. Sen de kısaca özetleyerek bu süreci hızlandırabilirsin:

✅ Örnek istem
"Bu proje basit bir öğrenci takip web sitesi. HTML/CSS/JavaScript kullanıyor, veri şu an tarayıcı hafızasında (localStorage) tutuluyor. Önce projeyi incele, kısaca ne iş yaptığını özetle."

Birden fazla klasör ve proje üzerinde çalışma

Claude Code'u her zaman üzerinde çalışmak istediğin projenin ana klasöründen başlatmalısın. Aynı anda birden fazla projeyle ilgilenmen gerekiyorsa, her proje için ayrı bir terminal oturumu (veya VS Code penceresi) açman önerilir — bu, bağlamların birbirine karışmasını önler.

3Kod üretme, düzenleme, test etme ve hata ayıklama

Claude Code'a; yeni bir özellik ekletmek, mevcut bir hatayı düzeltmek ya da bir bölümü yeniden düzenlemek (refactor) gibi görevler verebilirsin. Modül 3'te öğrendiğin "brief hazırlama" ve "plan-onay döngüsü" ilkeleri burada tam anlamıyla devreye girer.

✅ Örnek görev
"'index.html' sayfasındaki öğrenci listesi tablosuna bir 'arama kutusu' ekle. Kullanıcı isim yazdıkça tablo anlık filtrelensin. Önce nasıl yapacağını kısaca planla, sonra uygula."

Slash komutları ve proje komutları

Claude Code içinde / ile başlayan özel komutlar bulunur — örneğin geçmişi temizlemek, mevcut planı görüntülemek veya proje ayarlarını değiştirmek için kullanılırlar. Kendi projene özel, sık tekrarlanan işlemler için de kendi özel komutlarını tanımlayabilirsin.

4Git sisteminin temel çalışma mantığı

Git, kod değişikliklerinin zaman içindeki geçmişini kaydeden bir sürüm kontrol sistemidir — bir nevi projenin "geri al" düğmesi ve zaman makinesidir.

Repository, commit, branch ve version kavramları

TerimAnlamı
Repository (Repo)Bir projenin tüm dosyalarının ve değişiklik geçmişinin saklandığı yer.
CommitBelirli bir andaki değişikliklerin, açıklayıcı bir notla birlikte kaydedilmesi ("anlık fotoğraf").
Branch (Dal)Ana koddan ayrılan, bağımsız denemeler yapabileceğin paralel bir çalışma hattı.
Version (Sürüm)Projenin belirli bir commit noktasındaki hâli.

Yapay zekâ ajanıyla Git komutları çalıştırma

Claude Code'dan doğrudan Git komutlarını senin adına çalıştırmasını isteyebilirsin — komutu ezbere bilmen gerekmez, ne yapmak istediğini söylemen yeterlidir.

# Sık kullanılan temel Git komutları (Claude'a da aynı şekilde yazdırabilirsin):

git init                      # Klasörü bir Git deposu hâline getir
git status                    # Nelerin değiştiğini göster
git add .                     # Tüm değişiklikleri kayda hazırla
git commit -m "İlk sürüm"     # Değişiklikleri açıklamalı olarak kaydet
git log --oneline             # Kayıt (commit) geçmişini kısaca listele

Değişiklikleri kaydetme ve önceki sürüme dönme

Her anlamlı değişiklik grubundan sonra bir commit almak (Claude'a "şimdi bu değişikliği kaydet" demek yeterlidir), ileride "üç gün önceki hâline dön" diyebilmeni sağlar.

5Hatalı işlemleri güvenli biçimde geri alma

🛟
Güvenlik ağın: commit almak

Düzenli commit alışkanlığı, deneme yapmaktan korkmamanı sağlayan en büyük güvenlik ağıdır. Bir değişiklik işleri bozarsa, Claude'a "son commit'e geri dön" demen yeterlidir.

6Lokal ve uzak sunucu üzerinde çalışan rutinler

Geliştirdiğin otomasyonlar iki şekilde çalışabilir: lokal (senin bilgisayarında, sadece o açıkken) ya da uzak sunucuda (7/24 çalışan bir bulut sunucusunda). Basit, ara sıra çalışan görevler için lokal yeterlidir; sürekli ve kesintisiz çalışması gereken görevler için bir sunucuya taşınması gerekir.

API, connector ve zaman tetikleyicili rutinler

Bir rutin üç şekilde tetiklenebilir: bir API çağrısı ile (başka bir sistem Claude'u tetikler), bir connector olayı ile (örn. yeni bir e-posta geldiğinde) veya bir zaman tetikleyicisiyle (Modül 6'daki Schedule gibi, belirli saatte).

7Teknik borç ve kontrolsüz kod üretiminin riskleri

Teknik borç, hızlı ama düzensiz üretilen kodun ileride biriktirdiği "faturadır" — anlaşılması zor, bakımı pahalı, hataya açık bir kod tabanı. Yapay zekâ ile hızlı kod üretmek bu riski artırabilir; bu yüzden düzenli commit almak, kodu okumak (kopyala-yapıştır yapmamak) ve karmaşık kısımları küçük adımlara bölmek (Modül 3) teknik borcu azaltır.

Projenin profesyonel geliştiriciye devredilmesi gereken durumlar

  • Uygulama gerçek kullanıcı ödemesi veya hassas kişisel veri işlemeye başladığında
  • Kullanıcı sayısı/trafik, tek kişinin yönetebileceği ölçeğin üzerine çıktığında
  • Güvenlik açığı şüphesi olduğunda ve bunu bağımsız doğrulayamadığında
  • Yasal uyumluluk (KVKK, sektörel mevzuat) gerektiren bir aşamaya geçildiğinde

Bu durumların hiçbiri "başarısızlık" değildir — tam tersine, projenin büyüdüğünün ve doğru zamanda doğru desteği aradığının bir işaretidir. Bu konuyu Modül 10'da daha da derinleştireceğiz.

Modül çıktısı

Yapay zekâ ajanıyla kontrollü kod geliştirebiliyor, Git ile sürüm takibi yapabiliyor ve hatalardan güvenli biçimde geri dönebiliyorsun.
